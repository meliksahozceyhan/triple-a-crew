# Profile format

`.crew/profile.md` at the project root: YAML frontmatter for values skills read, then free-form notes.
It is committed with the code. Keep it under about 60 lines: it points to convention files rather than
copying them.

```markdown
---
stack: [typescript, pnpm, turborepo, prisma, vitest]
verify:
  - pnpm lint
  - pnpm typecheck
  - pnpm test
tests: ["packages/**/test/**/*.test.ts", "apps/**/*.test.ts"]
conventions: [CLAUDE.md, .claude/rules/, .cursor/rules/]
issue_tracker:
  tool: linear
  team: SHOP
  labels: [follow-up]
  confirm: always
organizer: proactive
models: {}
---
- Monorepo: deployable apps in `apps/*`, shared libraries in `packages/*`.
- Integration tests need Postgres and Redis running (`docker compose up -d`).
- `packages/database/src/generated/` is generated by Prisma; never edit it by hand.
```

## Fields

| Field | Type | Set by | Read by |
|---|---|---|---|
| `stack` | list of strings | detected | every skill, as context |
| `verify` | ordered list of shell commands, run from the root | detected | the verifier and the verify phase |
| `tests` | list of globs relative to the root | detected | the test engineer |
| `conventions` | list of paths relative to the root | detected | the organizer's size-L plan check, `test-harden` and every employee brief |
| `issue_tracker.tool` | `linear`, `github`, `jira`, `gitlab`, `asana`, `clickup`, `notion`, `local`, or another tracker's name | user, from detected candidates | `file-issue` |
| `issue_tracker.team` | Linear team, GitHub `owner/repo`, Jira project key, GitLab `group/project`, Asana project, ClickUp list, Notion database | user, from detected candidates | `file-issue` |
| `issue_tracker.labels` | list of existing label names added to every issue | user | `file-issue` |
| `issue_tracker.confirm` | `always` (default), `batch` or `never` | user | `file-issue` |
| `organizer` | `proactive` (default) or `manual` | user | the organizer |
| `models` | overrides of the staffing tiers: `mechanical`, `standard`, `critical`, each a model alias such as `haiku`, `sonnet`, `opus` or `fable` | user | the organizer's staffing |

**Detected** fields are refreshed by `onboard` whenever the repository changes. **User** fields are only
changed when the user asks.

## Rules

- Every field is optional. A skill that needs a missing field detects it for the task at hand or asks.
- Keys a skill does not recognize are left exactly as they are.
- Never put secrets, tokens or environment values in the profile.
